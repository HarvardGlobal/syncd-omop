Runbook · OMOP CDM 5.4 · OHDSI ARES

SYNCD setup guide

How to rebuild the synthetic concurrent disorders dataset from scratch: generate the patients, load them into PostgreSQL as OMOP CDM 5.4, and browse the result in OHDSI ARES. Run every command from the project folder synthea_concurrent_disorders/.

What you end up with

10,000 adultsSynthetic. No real patients.
NSDUH 2024Mental illness and substance use disorder rates by age and sex
OMOP CDM 5.4PostgreSQL database synthetic_concurrent
ARES viewerhttp://localhost:8085

Pick a starting point

A. Load the data I sent (recommended)

Use the Synthea CSVs in output/expansion_10000/csv/. On GitHub they are the syncd_expansion_10000_csv.zip file on the repo's Releases page; unzip it into output/expansion_10000/. Skip stage 2 and start at stage 3. You get exactly the same database.

B. Regenerate everything

Re-estimate the rates from the NSDUH file and re-run Synthea. With seed 12345 you get the same patients. Do every stage.

Before you start

  • Computer: the scripts were written on a Mac with Homebrew. On Linux, change the psql path in scripts/06a_load_vocab.sh and the POSTGRES_PATH line in scripts/06_load_omop.R.
  • Disk: about 20 GB free. The database is about 12 GB and the vocabulary files about 3 GB.
  • Memory: 16 GB is enough.
  • Time: about 4 hours in total. Most of that is the ETL in stage 4, which runs on its own.
  • Software:
    • Java 11 or newer (16 was used)
    • Python 3.10 or newer with pandas, numpy and scipy
    • R 4.3 or newer
    • PostgreSQL 16
  • Free Athena account at athena.ohdsi.org. You need it to download the vocabularies.
Download the vocabularies yourself. Athena's licence is per user, so the vocabulary files are not included in what I sent. Stage 3 explains which ones to choose.
1

Install the tools and create the database

~20 min

Install PostgreSQL and start it:

brew install postgresql@16 && brew services start postgresql@16

Create the database and its three schemas. synthea holds the raw CSVs, cdm holds the OMOP tables and results holds the ARES statistics.

/opt/homebrew/opt/postgresql@16/bin/createdb synthetic_concurrent
/opt/homebrew/opt/postgresql@16/bin/psql -d synthetic_concurrent -c "CREATE SCHEMA synthea; CREATE SCHEMA cdm; CREATE SCHEMA results;"

Install the OHDSI R packages. These are the versions used: DatabaseConnector 6.4.0, ETLSyntheaBuilder 2.1, Achilles 1.7.2, DataQualityDashboard 2.9.1 and AresIndexer 0.2.0.

Rscript -e 'install.packages(c("remotes", "DatabaseConnector", "Achilles"), repos = "https://cloud.r-project.org")'
Rscript -e 'remotes::install_github("OHDSI/ETL-Synthea", upgrade = "never")'
Rscript -e 'remotes::install_github("OHDSI/DataQualityDashboard", upgrade = "never")'
Rscript -e 'remotes::install_github("OHDSI/AresIndexer", upgrade = "never")'

The scripts connect as your login user with no password, which is the Homebrew default. To connect differently, set OMOP_DB_SERVER, OMOP_DB_PORT, OMOP_DB_USER and OMOP_DB_PASSWORD.

2

Generate the synthetic patients

~30 min · path B only

You need two files for this stage:

  • The NSDUH 2024 public use file (tab-delimited, from SAMHSA). It goes in source_data/nsduh_2024/NSDUH_2024_Tab.txt.
  • The Synthea 3.3.0 jar. It goes in tools/synthea-with-dependencies.jar. If it is missing, download it from the Synthea v3.3.0 release.
# 1. Survey-weighted rates from NSDUH -> calibration/
python3 scripts/01_estimate_nsduh.py source_data/nsduh_2024/NSDUH_2024_Tab.txt calibration
# 2. Build the Synthea modules and generate 10,000 patients (writes output/expansion_10000/)
scripts/03_generate.sh 10000 12345 expansion_10000
# 3. Check the generated rates against NSDUH
python3 scripts/04_validate.py output/expansion_10000 calibration/calibration.json

The validation report is output/expansion_10000/validation/validation_report.md. 03_generate.sh will not overwrite an existing run folder, so rename or move the old one first.

3

Download the OMOP vocabularies

~15 min + Athena email

Log in to Athena, open Download and tick the following vocabularies. Athena includes the small OMOP default vocabularies automatically.

  • SNOMED, RxNorm, RxNorm Extension, LOINC, CVX and UCUM
  • Gender, Race and Ethnicity. These were missing from the bundle this project used, so 06c adds them by hand. If you tick them, 06c does nothing.
  • Optional: ICD10CM. Without it, about 7,500 dental condition rows are dropped. No mental health or substance use row is affected.

Athena emails you a zip link. Unzip it into source_data/athena_vocab/, which should then contain CONCEPT.csv, CONCEPT_RELATIONSHIP.csv and the other vocabulary files.

Skip the CPT4 step. The Athena readme describes it, but nothing in this dataset uses CPT4 codes.
4

Load into OMOP CDM 5.4

~3 hours, mostly unattended

Run these five commands in order. Logs go to omop_load/. The first run also downloads the PostgreSQL JDBC driver into omop_load/jdbc/.

# a. Create the CDM and Synthea tables, then bulk-load the CSVs into the synthea schema (~5 min)
Rscript scripts/06_load_omop.R staging
# b. Stream the vocabulary files into cdm.* with COPY (~15 min)
scripts/06a_load_vocab.sh source_data/athena_vocab
# c. ETL-Synthea: build the OMOP event tables and indexes (~165 min)
Rscript scripts/06_load_omop.R etl
# d. Put the PHQ-9 / GAD-7 / AUDIT-C / DAST-10 scores back (the ETL drops them)
/opt/homebrew/opt/postgresql@16/bin/psql -d synthetic_concurrent -f scripts/06b_fix_screening_scores.sql
# e. Add the gender, race and ethnicity concepts if the vocabulary bundle lacks them
/opt/homebrew/opt/postgresql@16/bin/psql -d synthetic_concurrent -f scripts/06c_add_demographic_concepts.sql

If you load a CSV folder other than output/expansion_10000/csv, pass it as a second argument to the staging step: Rscript scripts/06_load_omop.R staging path/to/csv.

Re-run step d after every ETL run. If you skip it, the screening score columns are empty.
5

Check the load

~1 min

The numbers should match the table at the bottom of this page. Here are three quick checks:

/opt/homebrew/opt/postgresql@16/bin/psql -d synthetic_concurrent -c "
SELECT 'person' AS check, count(*) FROM cdm.person
UNION ALL SELECT 'condition_occurrence', count(*) FROM cdm.condition_occurrence
UNION ALL SELECT 'screening scores filled', count(value_as_number) FROM cdm.observation
  WHERE observation_source_value IN ('44261-6','70274-6','75626-2','82667-7','55758-7');"

Expected results: 10,000 people, 87,580 condition rows and 95,673 screening scores.

The ground-truth group of every person is in output/expansion_10000/validation/person_ground_truth.csv. Counting people by the 8 diagnosis codes in cdm.condition_occurrence gives these group sizes:

  • Both: 769
  • Mental illness only: 1,426
  • Substance use disorder only: 979
  • Neither: 6,826
6

Build the ARES viewer

~5 min

ARES is OHDSI's browser for an OMOP database. It is a static web app, so it needs no Docker and no server software.

The project already includes the built viewer for this database, so you can skip to stage 7 unless you rebuilt the database. To build it yourself, first download the ARES 0.6 web app. Unzip it into the project and move its bundled sample data out of the way:

mkdir -p omop_viz/ares_app && cd omop_viz/ares_app
curl -LO https://github.com/OHDSI/Ares/releases/download/v0.6-beta/Ares.0.6.0-beta.zip
unzip -q Ares.0.6.0-beta.zip -d site -x "__MACOSX/*"
mkdir -p ../sample_data_removed && mv site/data/* ../sample_data_removed/
cd ../..

Next, compute the statistics and data quality checks and write them where ARES reads them (omop_viz/ares_app/site/data/):

Rscript scripts/07_run_ares.R all

This command runs four steps in order:

  1. Achilles, which produces summary statistics.
  2. The Data Quality Dashboard, which runs about 2,400 checks.
  3. Temporal characterisation.
  4. AresIndexer, which writes the files ARES reads.

To re-run a single part, pass achilles, dqd, temporal or index instead of all. The script also works around three version mismatches between the OHDSI packages; each fix is commented in the code.

Messages you can ignore:
  • "ignoring error on disconnect"
  • "Skipped performance index"
  • 46 errors on COHORT checks
7

Open it

instant
scripts/08_view_ares.sh

This serves the site at http://localhost:8085 and opens your browser. Press Ctrl+C to stop it. To use a different port, add it as an argument, for example scripts/08_view_ares.sh 9000.

Things to know before you analyse it

  • Study window: restrict analyses to 2024-01-01 to 2025-12-31. Synthea also writes older history, so about half the visits are earlier and some observation periods start in the 1940s.
  • Unmapped race: 288 people have race_concept_id = 0. Their Synthea race is native, hawaiian or other, and ETL-Synthea only maps white, black and asian.
  • Data quality failures: the 20 failed checks are known ETL-Synthea gaps, such as unset unit and status fields and odd drug supply values. None of them involve the mental health or substance use records.
  • Intended use: the data is for testing, teaching and building cohorts, not for estimating treatment effects. The disease timelines and treatment details are simulation assumptions documented in README.md.

If something goes wrong

ProblemFix
psql: command not found or wrong pathEdit the PostgreSQL path in 06a_load_vocab.sh and 06_load_omop.R to match your install. Run which psql to find it.
R runs out of memory loading vocabulariesUse 06a_load_vocab.sh (step 4b), not the vocab_etl stage. It streams the 1.7 GB relationship file through PostgreSQL.
Sex, race or age-by-sex charts in ARES are emptyRun 06c_add_demographic_concepts.sql, then Rscript scripts/07_run_ares.R all.
Screening scores are emptyRun 06b_fix_screening_scores.sql.
ARES shows "Synthea" sample data, or two sourcesThe bundled sample data is still in site/data/. Move it out as in stage 6.
ARES page is blank when opened as a fileARES must be served over HTTP. Use 08_view_ares.sh; do not double-click index.html.
Starting overRun dropdb synthetic_concurrent, then repeat from stage 1.
The full method, calibration targets and validation results are in README.md in the project folder. The ETL ran with ETLSyntheaBuilder 2.1 on Athena vocabulary v5.0 29-AUG-26.
